# Agate — release distribution

This repository holds the **published releases** of Agate, an application for
P2P synchronization of engineering documentation. It contains no source code:
the binaries are attached to each GitHub release as assets.

## Downloads

- Latest release: <https://github.com/pragmaticdev-ru/agate/releases/latest>
- All releases: <https://github.com/pragmaticdev-ru/agate/releases>
- Machine-readable latest pointer: [`latest.json`](latest.json)

Every release ships **two x64 builds**, one per supported OS:

| Asset | Platform | Notes |
|---|---|---|
| `agate.exe` | Windows 10+ x64 (`x86_64-pc-windows-msvc`) | Portable single executable: no installer, no runtime DLLs, no Visual C++ Redistributable |
| `agate` | Linux x64 (`x86_64-unknown-linux-gnu`, glibc) | Portable single binary: X11 or Wayland; ALSA/PipeWire for voice meetings |

The asset file names are fixed (`agate.exe` and `agate`) because the in-app
updater addresses them by name. The platform and the architecture are shown on
the release page: in the release title, in the release notes, and as the
display label of each asset.

### Windows

Download `agate.exe` from the latest release and run it. The binary is
self-contained; it needs no installation and no additional runtime.

### Linux

Download the `agate` asset from the latest release, then:

```bash
curl -fLO https://github.com/pragmaticdev-ru/agate/releases/latest/download/agate
chmod +x agate
./agate
```

A desktop session (X11 or Wayland) is required for the window; voice meetings
also need ALSA or PipeWire. If a release has no `agate` asset, that release was
published Windows-only — the update channel then reports no Linux build instead
of offering an unusable one.

The release version is `0.<minor>.<N>`, where `<N>` is the source-repo build
number.

## Verifying a download

`sha256sums.txt` in the repository root lists one line per release asset:

```powershell
Get-FileHash -Algorithm SHA256 .\agate.exe
```

```bash
sha256sum agate
```

Compare the printed hash with the matching line in `sha256sums.txt`. The
`latest.json` pointer is additionally signed (Ed25519); the application verifies
that signature itself before installing an update.

## Repository layout

| Path | Purpose |
|---|---|
| `LICENSE` | BSD-3-Clause license of the project |
| `VERSION` | Version of the most recent release |
| `plugins/` | Converter-plugin API documentation shipped with the app |
| `sha256sums.txt` | SHA-256 of the release assets (Windows and Linux) |
| `latest.json`, `releases.md` | Metadata regenerated by CI on each release |
| `.github/workflows/publish.yml` | Finalizes a draft release and metadata |

The `Agate <version>` releases are produced locally and finalized by GitHub
Actions; the binaries are never committed to this repository's history.
